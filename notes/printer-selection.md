# 打印机选格修复：最近格缺料时不再卡死

## 症状（用户实机）

日志反复出现同一格：

```text
22:00:37  打印机: 缺方块材料 tile=19 目标=(3247,217)
22:00:39  打印机: 缺方块材料 tile=19 目标=(3247,217)
22:00:41  打印机: 方块 (3249,193) type=472 剩余=9146
22:00:43  打印机: 缺方块材料 tile=19 目标=(3248,217)
```

背包里 472 有 9000 多个，但打印机经常停住。

## 根因

`Printer.TryPlaceBlock` 扫描时只维护**一个**候选：距离最近的空位。扫完才 `FindItem` 查这一格的材料；没有就提示/日志并 `return false`。它不会回头找“远一点、但有材料”的格子，所以：

- 最近格缺料 → 整台打印机停住；
- 同一格每 2 秒重试 → 日志刷屏；
- 背包里明明有别的材料，也放不出去。

电线/促动器分支是同样的问题：先选最近格，再看电线/促动器够不够；不够就返回。

## 改法

### 方块（`TryPlaceBlock`）

1. 扫描时同时维护两个候选：
   - `bestAvailable`：材料**有**的最近格（用 `createTile -> slot` 字典判断）；
   - `bestAny`：所有空格中最近的一格（只用于“完全没料”提示）。
2. 优先放 `bestAvailable`。只有 `bestAvailable` 为空（范围内所有待放类型的材料都没有）时，才用 `bestAny` 报缺料并 `return false`。
3. 背包一次性建成 `createTile → 第一个非空 slot` 的 `Dictionary<int,int>`；循环里只查字典，不逐格 `FindItem`。语义仍是“按蓝图 `type` 精确匹配 `Item.createTile`”。
4. 缺料日志按类型聚合 + 5 秒限频：
   ```text
   打印机: 缺少材料，范围内无法放置: tile=19 ×37, tile=203 ×12, tile=44 ×5
   ```
   数量是该类型在范围内（空位、手长内、分层内、可打印）的待放格数；按数量降序，最多列 8 种。
5. `SetHint` 只列类型、最多 5 种：
   ```text
   打印机：范围内缺少材料：19, 203, 44
   ```

### 电线 / 促动器（`TryPlaceWire`）

1. 分别维护“材料够的最近格”和“所有待补格的最近格”。
2. 电线：按缺失颜色数 `CountBits(miss)` 判断电线总数是否够；放每段前重新 `FindItemByType(530)`，支持多堆电线。
3. 促动器：单独看 849 总数；有货才选最近促动器格。
4. 电线/促动器缺料也聚合 + 5 秒限频：
   - `打印机: 缺少电线材料，范围内无法补线: N 格`
   - `打印机: 缺少促动器，范围内无法放置: N 格`
5. 电线缺料不再挡住促动器；两边分别尝试。

### 性能

- 方块扫描：背包建表一次，循环内 `Dictionary.TryGetValue`；
- 电线/促动器：`CountItemByType` 两次，放置时最多 4 次 `FindItemByType`；
- 不会对每个蓝图格调用 `FindItem`。

## 涉及文件

- `tool/src/Printer.cs`

## 验证

1. 进游戏，NumPad7 开打印机。
2. 让背包只缺某种平台/方块（例如缺 tile=19），蓝图里同时有 472 等有料方块。
3. 期望：打印机继续放有料的 472/其它类型，不再卡在最近缺料格。
4. 日志：同一缺料类型 5 秒最多一条聚合提示，不再每 2 秒刷同一格。
5. 电线/促动器：只缺电线时，促动器仍能放；反之亦然。
6. 缺料提示最多列 5 种类型；方块日志的数量是范围内该类型的待放格数。

## 备注

- 选格只改“选哪一格”，不改变材料消耗、手长、分层、平台形状/帧恢复逻辑。
- 平台 `slope 3/4` 的保留逻辑不受影响（见 `notes/platform-frames.md` 4.3）。
